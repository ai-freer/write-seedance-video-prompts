# 图片资产生成与模型适配

本文件用于生产主要角色、Look、场景、道具和首尾帧等视频上游图片资产。视频目标固定为 Seedance 2.5；图片生成器可选择 GPT、Gemini、Seedream 或 Grok Image。

## 核心原则

- 先写一份统一视觉规格，再适配到一个选定的图片模型；
- 同一批资产一次只选择一个目标图片模型，避免在未校准时混用模型造成风格和身份漂移；
- 图片 Prompt 负责生产可复用资产，视频 Prompt 负责调用这些资产完成镜头；
- 不把图片模型专用参数写进统一视觉规格；
- 未核对当前模型文档时，不虚构参数名、权重语法、参考图上限或 API 字段。

## 统一视觉规格

### 角色身份

- 年龄段、族裔/地域特征和性别呈现；
- 头脸比例、脸型、下颌、颧骨、鼻、唇和耳朵；
- 肤色、肤质、雀斑/痣/疤等标志；
- 眼睛形状、虹膜颜色、眼神和眉形；
- 发型、发际线、发色和发质；
- 身高感、体型、肩颈和体态；
- 不可漂移项与允许变化项。

### Look

- 服装廓形、层次、颜色、面料和纹理；
- 鞋、首饰、眼镜、包和其他配饰；
- 妆容、发型变化和场景状态；
- 正面、侧面、背面必须一致的结构；
- 适用场景和不允许混入的其他 Look。

### 资产画面规格

- 视角和景别；
- 中性或指定表情；
- 站姿和手部是否可见；
- 背景、光线、镜头透视和色彩管理；
- 是否需要干净无遮挡、便于裁切和后续参考；
- 输出比例和分辨率要求。

## 主要人物生产顺序

先检查已有资产，足够时直接复用；只保留源视频人物的编辑任务不需要从头生图。新建角色时：

1. 建立视觉规格，生成候选身份图，选择并确认身份母版；
2. 快速路径只补身份近景/四分之三视角和当前 Look 的独立全身，不要求多视图；
3. 长/精细路径逐步建立多视图设定图、独立近景/全身和分镜真正需要的角度，不预制所有表情与服装；
4. 基于同一已批准母版派生本轮场景 Look；
5. 验收身份、服装结构与视图一致性，登记候选/批准状态，再组成引用包。

多视图用于整体校对，独立视图用于清晰引用；项目拥有整套设定图，不代表每次都上传整套。多人镜头的视图选择按 `seedance-2.5-reference.md` 的主体数量建议执行。

身份规格以稳定结构为主，表演中的眼神、情绪和动作另写为镜头状态；不要把“始终含泪”之类的临时情绪固化到中性母版。写实人物可选毛孔、雀斑、发丝状态、面料磨损等细节；卡通风格不强制真实皮肤纹理。

## 通用角色设定图 Prompt 骨架

```text
任务：为同一名角色制作[单视图/多视图]设定资产；如有多个视图，必须为同一个人。

角色身份：[统一视觉规格中的身份特征]。
当前Look：[服装、鞋、配饰、妆发和状态]。

画面要求：[正面全身、左/右侧面、背面、四分之三近景等所需视图]；中性站姿；比例一致；无遮挡；面部、发际线、体型和服装结构在所有视图中保持一致；[背景和光线要求]。

用途：作为 Seedance 2.5 的角色参考资产，因此身份辨识度、服装结构和视图清晰度优先于戏剧化构图。
不要出现：[其他人物、重复肢体、互相冲突的服装、水印、道具遮脸等任务相关错误]。文字策略：[无需文字，或仅允许指定视图标签]。
```

独立近景和全身优先独立生成；裁切图也需要逐张验收清晰度和结构，不能裁切后自动视为已批准。无参考图的产品资产可用“数量 + 颜色 + 形状/设计 + 物体 + 材质/磨损 + 辨识特征”，再按需要补角度。

## 模型适配器

适配器只改变表达格式，不改变统一视觉规格中的事实。

每次适配输出：

1. 目标模型名称和当前使用方式（网页、应用或 API）；
2. 需要上传的身份母版、Look 或场景参考图；
3. 一份可复制的目标模型 Prompt；
4. 若已从当前官方文档核实，列出支持的比例、质量或参考图设置；
5. 未核实项明确标为“使用界面默认值”，不猜测；
6. 生成后的验收清单。

### GPT

使用清晰的编辑/生成意图、引用图职责、必须保持项和允许变化项。强调这是同一角色的资产扩展，不把多个视图描述成多个人。

### Gemini

明确区分身份参考、服装参考和目标输出。若使用多张图，逐张说明作用；避免没有依据地声称特定权重或固定上限。

### Seedream

优先使用中文结构化视觉描述，保持角色身份、服装和画面规格的主次清楚。只有在核对当前产品界面后，才写入具体参数或参考模式。

### Grok Image

用直接、可视化的自然语言描述目标编辑或生成结果，明确身份不变和要改变的 Look/视角。未验证当前功能时，不承诺角色锁定强度或专有控制语法。

## 生成和批准

若当前环境存在可用图片生成工具：

1. 先向用户展示视觉规格、目标模型和本轮要生成的资产清单；
2. 确认已有授权覆盖本轮模型、清单与成本后执行；未覆盖才追问，不额外扩大生成规模；
3. 把结果登记为 `candidate`；
4. 对照身份、Look、结构和技术质量逐项验收；
5. 用户批准后改为 `approved`。

若没有工具或用户暂不生成，只交付目标模型 Prompt 和上传说明，不伪造资产状态。

## 验收清单

- 是同一个人，而不是“相似的人”；
- 脸型、五官比例、发际线、发色、肤色和标志特征一致；
- 身高感、体型和肩颈比例一致；
- Look 的服装结构、颜色、材质、鞋和配饰一致；
- 正侧背视图没有结构矛盾；
- 手部、眼睛、牙齿和配饰没有明显生成错误；
- 背景、构图和光线适合作为参考，不抢主体；
- 文件可单独识别，命名和登记表一致；
- 候选资产没有覆盖已批准版本。

若身份通过但服装失败，只重做 Look 资产；若某个角度失败，只补该独立视图。不要无必要地重新生成整套已批准资产。
