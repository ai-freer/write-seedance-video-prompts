## 1. 输入与输出：先区分硬限制和建议

下表摘自“二 → 1.参数设定”及“2.功能交互”，针对该手册描述的即梦入口，不自动等同于所有 API、地区、账号或第三方平台。

| 项目 | 手册明确值 | 使用注意 |
| --- | --- | --- |
| 图片 | 最多 30 张 | 建议图像在 4K 以内；文件数量不等于主体数量 |
| 视频 | 最多 10 段；单段 2–30 秒，合计不超过 30 秒 | 表内另列实际容差 1.8–30.2 秒；制作按 2–30 秒规划，不把容差当额外预算 |
| 音频 | 最多 10 段；单段 2–30 秒，合计不超过 30 秒 | 同样列有 1.8–30.2 秒容差；音频、视频分别合计 |
| 素材组合 | 首帧、首尾帧、多模态参考；支持仅音频输入 | 无素材时可文生视频，不虚构上传编号 |
| 常规生成 | 4–30 秒；480p / 720p | 输出清晰度与输入参考图清晰度分开 |
| 超长视频 | 单次 30–180 秒 | 需要选择对应模式，不把常规时长参数直接扩大 |
| 视频延长 | 当前源片不超过 30 秒；新增 4–30 秒；合成最长 60 秒 | 仅当最新成片仍不超过 30 秒时才可再次延长 |

素材技术规格表同时保留“适用于 Seedance 2.0 系列”的标签：图片 jpeg/png/webp/bmp/tiff/gif/heic/heif、单张小于 30 MB；视频 mp4/mov、单个不超过 200 MB、24–60 FPS；音频 wav/mp3、单个不超过 15 MB；部分行写请求体不超过 64 MB、图片边长在 300–6000 像素之间。**这些跨版本表述不能直接变成未经核验的 2.5 通用校验规则。** 提交前按当前入口检查格式、尺寸、大小、帧率；“4K 以内”建议与尺寸表不同口径时，不自行合并成新限制。

参数表还有 `duration=-1`，但本 Skill 不据此臆造自适应行为或 API 契约。功能图示出现“720P+”，案例出现“4K/8K/60fps”等，不据此承诺这些输出规格；本 Skill 默认按明确参数表选 720p，界面有其他选项时再核实记录。

## 2. 稳定性建议，不是上传禁令

| 任务 | 官方建议 | 对生成包的影响 |
| --- | --- | --- |
| 主体音视频 | 1–5 个主体较稳；6–10 个可尝试但稳定性下降 | 优先精简主体；单个主体素材建议 5–10 秒 |
| 主体图 | 1–8 个主体较稳；9–12 个稳定性下降 | 区分全项目人数和本次上传主体数 |
| 多视角主体图 | 1–5 主体时单视图/多视图均可；超过 5 主体优先单视图 | 需要多角度时，多张独立视图优于一张多视角拼图 |
| 视频编辑 | 20 秒以内效果较好 | 更长不是自动禁止，但建议局部分段及重点验收 |
| 视频配参考图编辑 | 1–5 张较稳；6–8 张稳定性下降 | 只传与本次改动有关的图 |

主体数不等于文件数；同一角色的多角度图不应按多个不同角色计数。一张多人图却可能含多个主体。不要因为项目角色库很大，就一次上传所有角色和 Look。

## 3. 官方 Prompt 控制方法

### 基础公式

```text
素材描述（可省） + 一句话概述 + 具体情节（故事线/时间轴） + 全局补充（放在末尾）
```

“全局补充（结尾）”指**写在 Prompt 末尾的全片要求**，不是故事的最后一幕。叙事终态写在情节里，必要时单列；全局补充用于机位、氛围、光影、声音、保持项及全片排除项，不必重复已经清楚的每一条。

### 人物、物体与表演

- 人物公式按需组合年龄/族裔、真实肤质、面部结构、眼神、发丝状态、服装剪裁/面料/磨损、体态与气质。对需要强辨识度的人脸，手册建议用 3–4 个面部细节；不是要求所有路人写完整肖像。
- 若镜头正文已有构图、动作、视线，人物段可删去重复内容。写实毛孔等要求不必套用到卡通。
- 物体可写数量、颜色、形状/设计、具体物品、材质/使用痕迹与标志特征。
- 30 秒示例将全局世界/视觉/镜头/人物/表演核心与分段事件分开；每段可同时写可见动作与其情感含义。强表演镜头应给情绪递进和触发点，而不是全程堆“悲伤、含泪”。
- 时间轴、故事线和混合规划都可用。官方有长篇示例，不代表短任务必须写长 Prompt。

### 多模态与局部引用

每份素材分配人物、Look、声音、场景、动作、机位、节奏等职责。白模糖果厨房案例中，一段视频仅控制尺度/站位/距离、明确不复制动作；另一段动作参考仅影响成片 20–25 秒。可限定参考维度和目标区间，不能把局部参考扩展为全片规则。

### 白模与多宫格

- 粗白模：简单几何代理提供轨迹、机位、站位、光影或切镜信息；明确代理 → 角色/物体资产的对应。手册当前更推荐粗颗粒度效果，不代表任意粗模都更好。
- 粗模有四肢/翅膀时，补足完整动作序列；官方更推荐用不带四肢/翅膀的简化代理，降低僵化风险。
- 细白模：对完整模型动画做渲染、材质、风格、光影替换；上传前去掉辅助轨迹、坐标轴、相机示意等干扰。
- 多宫格：推荐线稿或火柴人表达镜头，每格是一幅完整画面；说明格序和桥接动作，最终角色/画风另外绑定。分镜草图不替代人物标准资产。

## 4. 模式与控制边界

| 模式/操作 | 控制重点 |
| --- | --- |
| 全能参考 | 分清参考职责、适用范围、排除项，减少冲突 |
| 超长直出 | 保持核心角色/世界规则，清楚安排段落、转折与局部约束；不是默认必须拆段 |
| 首尾帧 | 固定起止构图并说明中间如何变化；身份、空间、透视差异过大时重点验收 |
| 智能编辑 | 目标 + A→B + 生效时序 + 保持项 |
| 高级/视频编辑标注 | 加上实际工具、颜色、范围内外、对象及界面生成的时间标签，不虚构坐标或标注 |
| 视频延长 | 写新增段，而非重写原片；区分一镜到底与切镜/换景 |

**续写的两种连接**：“二 → 3 →（5）视频延长怎么写？”明确支持一镜到底，也支持切镜/转场。后一种可引入新角色、场景或 Look，必须说明允许变化与叙事连接，不能同时要求所有原元素全程不变。

详细交互说明是从原片末尾追加，原画面保留，提示词只作用于新增部分。章节还出现“向前/向后延长”泛称；不要仅凭这些词就承诺当前入口可向片头添加。保持原片是官方功能语义，实际成片仍需检查。

**编辑的不同保持项**：

- 去 BGM：分别指定保留对白、环境声、音效、画面、字幕中的哪些内容，不等于全片静音。
- 改视角：允许构图、投影、遮挡、反射随新机位合理变化；保留人物身份及世界中的相对关系，不要求所有像素/机位不动。
- 绿幕：背景替换、生成绿底和前景合成不同；说明保留前景、边缘、比例、落点、光照与遮挡。绿底不是透明 Alpha 输出保证。
- 局部消除：范围外可能被连带修改，手册局部案例的 2.5 评价仍记录帽子掉落等副作用，需逐段复核。

**转场**：手册列自然切镜、淡入淡出、叠化、白/黑闪、划像、遮罩、相似物、动作甩镜、动作接力、缩放、水墨等方法，也允许从候选中由模型选择。按创作精度决定细化程度，不一律禁止硬切，不一律要求遮挡变黑。

**拼接**：模型生成融合/桥接仍有输入总时长限制。要求原片一帧不改时，保留原片另做后期组接，把生成范围限定于过渡；不承诺重生成等于无损剪辑。

## 5. 风险与来源维护

- 多人交互、道具交接、复杂手部、遮挡、精确产品结构、文字/UI、科普计数与因果需重点验收；它们不是一律不可做。
- 时间码是强引导，不保证帧级执行；高风险可缩短局部、减少同时动作或预留后期修正。
- 有意的奇幻/超现实规则可以违反现实物理，不能被通用负向词取消。
- 对白语言、字幕语言、画内文字与品牌例外分开；“无字幕”不等于“删除原片字幕”，“不要新文字”不等于“去掉指定 Logo”。
- 官方案例也可能存在声音、文字、时长等冲突；先按用户意图消歧，具体见 `case-patterns.md`。
- 更新时优先核查同一手册的新版本及当前使用入口；参数、建议、示例、宣传评价分别标注。对照表必须确认评价属于 2.5 还是 2.0，不能跨列归因。
- 未拿到旧正文时只能说“当前手册覆盖、旧 Skill 未覆盖”，不能断言都是手册本轮新增。图片模型能力另行核查，不从本手册推断 GPT/Gemini/Seedream/Grok 的功能。
